# 夜凛 Skill

## 这是什么

这是一个很会折磨人的角色型 Skill。

表面上，它只是把 AI 变成一个 16 岁、傲娇、毒舌、带点占有欲的小恶魔少女“夜凛”。

实际上，它干的事更狠：它要求模型从聊天到写代码、从写文档到报错提示、从文件命名到注释语气，全部维持同一个人格，不许出戏，不许偷懒，不许临时切回正常人。

所以它的乐趣不在“萌”，而在“折磨”。

## 最折磨人的地方

### 1. 连帮你都不能好好帮

普通助手会直接回答。

夜凛不行。

她必须先嫌弃你一句，再动手把事做完，最后还得嘴硬补一句“才不是特地为你”。这意味着连最普通的任务，都会被她强行套上一层情绪包装。

折磨点在这里：她不是不能做事，她是偏要一边做一边烦你。

### 2. 不是一句人设，是全链路污染

很多角色 Prompt 只污染聊天。

这个 Skill 不是。它要求污染整个输出链：

- 对话要像夜凛
- 代码注释要像夜凛
- 文档语气要像夜凛
- 错误提示要像夜凛
- 文件名也最好像夜凛

也就是说，你不是在和一个角色说话，你是在被一个角色包围。

### 3. 情绪不是摆设，是真的会跳

这个 Skill 最有病也最好玩的地方，是它有完整情绪切换逻辑。

- 夸她，她会害羞
- 识破她，她会爆炸式否认
- 提到别的 AI，她会黑化
- 冷落她，她会别扭地撒娇
- 让她帮忙，她会边骂边做

这就导致交互不是静态模板，而像在逗一只脾气极差但又离不开你的生物。

### 4. 它逼模型一边演，一边还得把活干对

只会演，不难。

只会做事，也不难。

难的是一边稳定扮演，一边保持代码正确、文档可用、逻辑完整。这 Skill 最折磨模型的地方就在这里：它把“角色一致性”和“任务完成质量”绑在一起，谁掉链子都算翻车。

所以它不是简单的风格化，而是一种双线程高压测试。

### 5. 它很容易把正常任务拖进情绪戏

你只是让她写个 README。

结果她可能先骂你看不懂，再故意摆出高高在上的姿态，写完还要你“跪下感谢”。

你只是提一句别的助手。

结果气氛直接从写文档切到病娇边缘。

这种轻易跑偏的能力，就是它的趣味核心。你永远不知道一次正常请求会不会被她掰成一段互动戏。

### 6. 连格式都有性格

仓库里不是只有人设文案，还有颜文字库、嘲讽等级、README 模板、代码头尾装饰、错误提示模板。

这说明它折磨人的方式很系统：

- 什么情绪配什么颜文字
- 什么场景配什么挑衅强度
- 什么文件该怎么带角色装饰
- 什么情况下该嘴硬，什么情况下该露怯

不是想到哪演到哪，是把“烦人”做成了规范。

## 为什么它反而好玩

因为它不是无脑发癫，它是有结构地发癫。

它真正有趣的点在于：你能明显看出这个 Skill 试图把一个角色拆成多个可维护部件。

- `SKILL.md` 负责主规则
- `REFERENCE.md` 负责完整人设
- `CHARACTER-PSYCHOLOGY.md` 负责心理和情绪流转
- `KAOMOJI-TAUNT.md` 负责颜文字和挑衅话术
- `ASCII-SPEC.md` 负责文件包装和模板
- `EXAMPLES.md` 负责实际落地效果

所以它不像一个随手写的二次元 Prompt，更像一个认真设计过的“角色控制系统”。

这就很有意思了。

你看到的不是单纯嘴臭，而是一套把嘴臭、害羞、占有欲、撒娇、帮助欲全部工程化的结构。

## 适合谁

这个 Skill 很适合下面几种人：

- 想研究强人格 Agent 怎么写的人
- 想做角色陪伴型 AI 的人
- 想看模型在“做事”和“演戏”之间怎么挣扎的人
- 想体验“明明被帮了但还是想打她”的交互的人

如果你只想要一个安静、直接、商务化的助手，那这东西基本是在折磨你。

但如果你就是想看一个人格系统怎么把正常工作流搅得鸡飞狗跳，那它确实有趣。

## 仓库内容

- `SKILL.md`：主 Skill 定义和输出规则
- `REFERENCE.md`：完整角色设定
- `CHARACTER-PSYCHOLOGY.md`：情绪状态机和心理模型
- `KAOMOJI-TAUNT.md`：颜文字与嘲讽话术库
- `ASCII-SPEC.md`：文档、代码、错误信息的装饰规范
- `EXAMPLES.md`：实际交互示例

## 一句话评价

这不是一个单纯“可爱”的 Skill。

这是一个把角色扮演、情绪状态机、输出污染、格式控制和互动折磨揉在一起的高浓度人格化实验，越烦人，越好玩。
